# C# Code Style

Эти правила применяются ко всему C#-коду проекта. Если существующий файл использует немного другой стиль, сохраняй локальную согласованность и не смешивай стилевой рефакторинг с функциональной правкой.

## Форматирование

- Используй четыре пробела для отступа; табуляцию не используй.
- Ставь открывающую фигурную скобку на новой строке (Allman style).
- Не оставляй пробелы в конце строк и лишние пустые строки.
- Используй одну инструкцию на строку и фигурные скобки для многострочных блоков.
- Короткие guard clauses могут не иметь фигурных скобок, если тело состоит из одной простой инструкции и это соответствует соседнему коду.
- Сохраняй `using` в начале файла: сначала пространства имён .NET, затем проекта и сторонних библиотек, затем Unity; удаляй неиспользуемые директивы.

## Именование

- Типы, методы, свойства, события и публичные члены именуй в `PascalCase`.
- Локальные переменные и параметры именуй в `camelCase`.
- Приватные поля именуй в `_camelCase`.
- Интерфейсы начинай с `I` (`ISceneChanger`); параметры типов — с `T`, если это улучшает читаемость.
- Булевы значения называй как утверждение или вопрос: `isReady`, `hasValue`, `CanLoad`.
- Не используй неочевидные сокращения и однобуквенные имена вне коротких индексов или общеупотребимых математических выражений.
- Имя файла должно совпадать с именем основного публичного типа. По возможности размещай один публичный тип в файле.

## Объявления и сериализация

- Явно указывай модификатор доступа.
- Поля инспектора объявляй как `[SerializeField] private`; не делай поле публичным только ради сериализации.
- Предпочитай свойства публичным изменяемым полям.
- Используй `var` только когда тип очевиден из правой части; в остальных случаях указывай тип явно.
- Используй target-typed `new()` только когда тип однозначно виден из объявления или сигнатуры.
- Для неизменяемых после создания зависимостей и состояния используй `readonly`, если это совместимо с Unity serialization.

## Структура класса

Располагай члены в следующем порядке, пропуская отсутствующие группы:

1. Константы и статические поля.
2. Сериализованные поля.
3. Остальные поля.
4. Конструкторы и Unity lifecycle methods.
5. Публичные свойства, события и методы.
6. Защищённые члены.
7. Приватные методы.
8. Вложенные типы.

Не добавляй `#region` только для повторения этой структуры.

## Читаемость

- Предпочитай guard clauses глубокой вложенности.
- Выноси сложные условия в хорошо названные переменные или методы.
- Комментарий должен объяснять причину или ограничение, а не пересказывать код.
- Не оставляй закомментированный код. Для временно незавершённой работы используй конкретный `TODO` с объяснением следующего шага.
- Не выполняй массовое переформатирование несвязанных строк или файлов.
